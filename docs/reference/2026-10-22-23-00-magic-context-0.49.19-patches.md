## no-session-model-fallback

0.49.16 changed the line the patch replaces (release note: "Configured historian chains no longer fall
back to the active session model when exhausted (issue 740)"). `runFallbackHistorianPass`
(`dist/v2/server-6vdzn1td.js` line 15623, `dist/index-rpxdjkm0.js` line 17674) now reads:

```js
const primary = toModelEntry(args.model);
for (const candidateInput of [
  ...args.fallbackModels ?? [],
  ...!primary && args.fallbackModelId ? [{ model: args.fallbackModelId }] : []
]) {
```

`args.model` is `ctx.historianModel` (server-6vdzn1td.js line 18751; the three callers of
`runValidatedHistorianPass`, lines 17376, 17967 and 18401, pass `model: deps.model`), and
`args.fallbackModelId` is still `ctx.fallbackModelId ?? resolveLiveModelKey(ctx.liveSessionState, sessionId)`
(line 18756), the live model of the session being summarised. Upstream therefore no longer appends the
session model when a historian model is configured, but still does whenever `historian.model` resolves to
nothing (no model configured, or a profile or failed configuration reload without one). The patch keeps
the chain to the configured fallbacks in that case too:

- find: `...!primary && args.fallbackModelId ? [{ model: args.fallbackModelId }] : []` (exactly once per file)
- replace: `...[] /* mc-patches: no-session-model-fallback */`
