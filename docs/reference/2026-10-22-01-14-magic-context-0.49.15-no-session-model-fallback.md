## The code

`async function runFallbackHistorianPass(args)` (server-dd0tz6cn.js line 16063, index-snp5wbge.js line
18113) builds the retry chain after the primary historian model failed:

```js
for (const candidateInput of [
  ...args.fallbackModels ?? [],
  ...args.fallbackModelId ? [{ model: args.fallbackModelId }] : []
]) {
```

`args.fallbackModelId` is the live model of the session being summarised. It is set by the callers:
`fallbackModelId: ctx.fallbackModelId ?? resolveLiveModelKey(ctx.liveSessionState, sessionId)`
(server-dd0tz6cn.js line 19170, where `resolveLiveModelKey` returns `providerID/modelID` from
`liveSessionState.liveModelBySession`), and in `dist/index.js` line 10390
`fallbackModelId: (() => { const model = resolveLiveModel(sessionId); … })()`. The run then logs
`compartment agent: retrying historian with <model> (session-model last resort i/n)`
(`const isSessionModelLastResort`, server-dd0tz6cn.js line 16097, index-snp5wbge.js line 18147).
No configuration key controls the append: the historian configuration schema
(`@cortexkit/opencode-magic-context/src/config/schema/magic-context.ts`, `OpenCodeHarnessBlockSchema`) has only `model`,
`fallback_models` and `variant`. The other `fallbackModelId` uses (prompt sizing, the failure log line)
read the value only; they do not run a model.

The dreamer is not affected: its tasks run on `configuredModels: [model, ...fallbackModels]` only
(`dist/v2/context-4qczzck7.js`).

## The patch

Replace, once in each file:

- find: `...args.fallbackModelId ? [{ model: args.fallbackModelId }] : []`
- replace: `...[] /* mc-patches: no-session-model-fallback */`

The chain is then exactly `fallback_models`; when it is empty or every entry fails, the existing
`if (chain.length === 0) return { ok: false, … }` / last-error path reports the failure and the
historian retries on a later turn.
