# Magic Context 0.47.0: why `execute_threshold_percentage: 13` is ignored, and the patch

Evidence for the patch `execute-threshold-min` (`patches/execute-threshold-min.ts`). Everything below
was read from the published package `@cortexkit/opencode-magic-context@0.47.0` and from this
machine on 2026-10-11.

## 1. The installed files are the published ones

`npm pack @cortexkit/opencode-magic-context@0.47.0` gives
`cortexkit-opencode-magic-context-0.47.0.tgz`, integrity
`sha512-ei7HuwbUiOPUa7fUtmOvYBChXwpOh02CA/+76xeNiEo0Lbmt0/tlcld2/DZw8R5r/HmDcY+O2eYx2pelffVvNw==`.
OpenCode 2.0.24 installed the same version at
`~/.cache/opencode/npm/@cortexkit/opencode-magic-context@0.47.0/1791693075785/node_modules/@cortexkit/opencode-magic-context/`.

| File | sha256 in the tarball | sha256 installed |
|---|---|---|
| `dist/v2/server-50hvkg3v.js` | `dd36bd4a24181727645ec0267ef1d67c657865cd914d842c9739eaecbabbb105` | same |
| `dist/index-m5fe6jch.js` | `6abe7e8c60c97bf35e9cf992ad9fe9936dc0557303a445a8c27859b47c94c3ba` | same |

`dist/v2/server-50hvkg3v.js` is part of the OpenCode 2 build (`dist/v2/`); `dist/index-m5fe6jch.js`
is the OpenCode 1 build. Among all `dist/**/*.js` files these are the only two containing
`min(20).max(90` (`grep -l`).

## 2. The configuration schema rejects values below 20

Source shipped in the tarball, `package/src/config/schema/magic-context.ts` line 1230:

```ts
execute_threshold_percentage: z
    .union([
        z.number().min(20).max(90, EXECUTE_THRESHOLD_CAP_MESSAGE),
        z
            .object({ default: z.number().min(20).max(90, EXECUTE_THRESHOLD_CAP_MESSAGE) })
            .catchall(z.number().min(20).max(90, EXECUTE_THRESHOLD_CAP_MESSAGE)),
    ])
    .default(DEFAULT_EXECUTE_THRESHOLD_PERCENTAGE)
```

Compiled, three occurrences of `min(20).max(90` per file:

| File | Lines |
|---|---|
| `dist/v2/server-50hvkg3v.js` | 5611 (number), 5612 (`default` and the per-model catch-all) |
| `dist/index-m5fe6jch.js` | 5636 (number), 5637 (`default` and the per-model catch-all) |

`DEFAULT_EXECUTE_THRESHOLD_PERCENTAGE = 65` (server-50hvkg3v.js:5199, index-m5fe6jch.js:5224).
`EXECUTE_THRESHOLD_CAP_MESSAGE` (line 5200 / 5225) explains only the upper bound ("capped at 90% for
cache safety"); nothing in the package explains the lower bound of 20.

On this machine `~/.config/cortexkit/magic-context.jsonc` has `"execute_threshold_percentage": 13`
(kept by the user's decision), and Magic Context's log
(`/tmp/opencode2/magic-context/magic-context.log`) records on every configuration load:

```
[2026-10-11T04:31:24.440Z] [config] config reload failed ~/.config/cortexkit/magic-context.jsonc: invalid configuration: [user config] "execute_threshold_percentage": invalid value (number 13), using default 65.
```

and, on every turn, the proactive floor that a threshold of 65 implies:

```
[2026-10-12T01:38:41.919Z] [magic-context][ses_…] compartment trigger: not firing at 27.9% — below proactive floor (63%)
```

## 3. The code that uses the threshold has no lower bound

`dist/v2/context-14v1hr8b.js` (the OpenCode 2 runtime):

- `resolveExecuteThresholdDetail` (line 1338) takes the configured number; it only replaces it when
  it is not finite or negative (line 1396: `if (!Number.isFinite(resolved) || resolved < 0)`) and
  caps it at the top (line 1399: `Math.min(resolved, MAX_EXECUTE_THRESHOLD)`, `MAX_EXECUTE_THRESHOLD = 90`).
- The proactive historian trigger (line 5487):
  ```js
  function getProactiveCompartmentTriggerPercentage(executeThresholdPercentage) {
    return Math.max(0, executeThresholdPercentage - PROACTIVE_TRIGGER_OFFSET_PERCENTAGE);
  }
  ```
  with `PROACTIVE_TRIGGER_OFFSET_PERCENTAGE = 2` (line 5431): 13 gives 11.
- Wrapup sizing (`dist/v2/server-nf82q6pt.js`) multiplies the context limit by the percentage, with
  `Math.max(1, …)`.

So a threshold of 13 is a valid input to everything after the schema.

## 4. The patch

Replace `min(20).max(90` with `min(1).max(90` (three times per file). Only the minimum changes; the
maximum of 90 and its message stay. The results:

| File | sha256 after |
|---|---|
| `dist/v2/server-50hvkg3v.js` | `58cb9f82d7f3e8c993b37b992c1af4c0f4727c077ef32eb8db71a26929ba373c` |
| `dist/index-m5fe6jch.js` | `559226c00606568d810b30a6fa9e6cbf5ab0d1acdcbf443590a960588099c7ff` |

Neither file contained `min(1).max(90` before, so the change is exactly reversible
(`tests/unit/patches/patches.test.ts` applies and reverses it on the real files).

## 5. How to see that it works

After `apply` and an OpenCode restart, `opencode-magic-context-patches effect` reads the log since the
server started: no more `config reload failed … execute_threshold_percentage` lines, and the
proactive floor logged as `11%` (threshold 13 − 2).

## 6. What it does not change

- The `magic-context` command on this machine (`~/.local/bin/magic-context`) is a wrapper for a
  separate build, `~/.local/share/opencode/plugins-build/magic-context/packages/cli/dist/index.js`
  (CLI package 0.42.6), whose bundle contains its own `min(20)` checks. The patch does not touch it,
  so `magic-context doctor` may still call 13 invalid. That is expected.
- With 13 % on a 1M-token model Magic Context starts compressing around 130k tokens and the historian
  around 110k, so it runs more often and uses more historian tokens than at the 65 % it has
  effectively used so far.
