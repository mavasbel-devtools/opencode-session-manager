# Magic Context 0.49.12: new file names, the same patch

Evidence for adding Magic Context 0.49.12 to `execute-threshold-min` (`patches/execute-threshold-min.ts`),
read from the published package on 2026-10-18. Earlier reasoning: from
`2026-10-11-19-37-magic-context-0.47.0-execute-threshold.md` to
`2026-10-16-17-03-magic-context-0.49.7-execute-threshold.md`. This document compares 0.49.12 with
the pristine published 0.49.7 (`npm pack @cortexkit/opencode-magic-context@0.49.7`, integrity
`sha512-dnvLs+YR…qP194Ew==`, equal to the registry's). 0.49.8–0.49.11 were never installed here
and are not added.

## 2. The schema still rejects values below 20

`package/src/config/schema/magic-context.ts` differs from 0.49.7's only in `.describe(…)` texts
(dreamer, smart notes, memory, historian timeout descriptions; one new description on the user-profile
schedule). Running the 0.49.12 source schema (`MagicContextConfigSchema.safeParse`, zod from the
installed 0.49.7 copy) on the live `~/.config/cortexkit/magic-context.jsonc` gives exactly one issue:
`execute_threshold_percentage` "Too small: expected number to be >=20". With that one value set to 20
the configuration is valid, including `execute_threshold_tokens` (`antigravity/gemini`,
`antigravity/claude`, `antigravity/gpt`: 80000).

## 3. The code that uses the threshold is unchanged

- Function texts (brace-matched, whitespace and log-helper numbering normalised), in `dist/v2` and in
  all of `dist`, identical in 0.49.7 and 0.49.12: `resolveExecuteThresholdDetail`,
  `modelKeyLookupOrder`, `resolveTokensMatchWithKey`, `resolveModelKey`, `resolveContextLimit`,
  `isFinitePositive`, `normalizeTrustedPercentageThresholds`, `makeProjectThresholdWarning`.
- All 7 call sites of `resolveExecuteThresholdDetail(` in `dist/v2` are identical with 300 characters
  of context on each side. With 500 characters they differ because of a refactor nearby:
  0.49.12 moves the m[0] render options into `createM0RenderOptions(controls, …)`
  (its source comment names the module `hooks/magic-context/render-options` of the Magic Context sources), called with the same `deps` object; the history-budget
  call `resolveHistoryBudgetTokens(…, executeThresholdPercentage, …)` keeps its arguments.
- Every expression mentioning `executeThresholdPercentage`, `execute_threshold_percentage` or
  `ExecuteThreshold` (60 characters each side, digits removed): 122 in the OpenCode 2 build and 148
  in the OpenCode 1 build in both versions; the 3 differing ones in each are that refactor
  (`deps.` → `controls.`, and an `if (…) return;` reformatted).
- Every assignment `executeThresholdPercentage: …` in `dist/v2` is the same list in both versions,
  including `config.execute_threshold_percentage` and
  `resolveExecuteThresholdDetail(config.execute_threshold_percentage ?? 65, …)`.
- `MAX_EXECUTE_THRESHOLD = 90`, `PROACTIVE_TRIGGER_OFFSET_PERCENTAGE = 2`: 13 still gives 11.
- The log lines `effect` reads are present as in 0.49.7: "transform threshold: model=" (1),
  "proactiveFloor=" (1), "below proactive floor" (2), "config reload failed" (1).
- Functions other tools rely on are unchanged: `seedV2ForkFromParent`, `openDatabaseAsync`.

## 4. Storage and release notes

`LATEST_SUPPORTED_VERSION = 95`, highest migration `version: 95`. The release notes of 0.49.8,
0.49.9, 0.49.10, 0.49.11 and 0.49.12 each state "No migration. `context.db` stays at schema 95 and
`store.db` at schema 63". Behaviour notes relevant here: 0.49.9 `/ctx-status` on OpenCode 2 shows the
session model's own threshold; 0.49.11 OpenCode 2 applies settings it used to ignore (history budget
is now part of the cache identity, auto-search hints on by default, commit indexing) and every
OpenCode 2 session rebuilds its cached prefix once on the first turn after the upgrade; 0.49.12
removes multi-second freezes in very long sessions and states existing configuration keys stay valid.

So the same three replacements make a configured 13 work as 13 on 0.49.12. The e2e test
`tests/e2e/lifecycle.test.ts` applies and undoes the patch on the fixture files and checks both
checksums. After updating to 0.49.12: `opencode-magic-context-patches apply`, restart OpenCode, then
`opencode-magic-context-patches effect` (expects `respected`).
