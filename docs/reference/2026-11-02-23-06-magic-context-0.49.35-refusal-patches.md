## 3. Which files OpenCode runs

The plan cited `dist/v2/context-znqfkap4.js`. That file is not executed by OpenCode 2.1.4:

- OpenCode resolves a plugin with `Host.resolve`
  (`/tmp/opencode/src-2.1.4/packages/plugin/src/host.ts:17-43`): it tries the `server` subpath,
  then `""`. The package has no `server` export, so the error `ERR_PACKAGE_PATH_NOT_EXPORTED` is
  skipped and `""` resolves to `dist/index.js`.
- `dist/index.js` imports `./context-fk8e3h9p.js`, which imports `./index-b6xz3qbe.js` (line 134).
- No package entry references `dist/v2/*`.

So the live sites are in `index-b6xz3qbe.js` (transform) and `context-fk8e3h9p.js` (v2 context
hook). `dist/v2/context-znqfkap4.js` holds a second copy of the same code. The matchers search
every `.js` file under `dist/` recursively (`NodeFilesAdapter.list`, `readdir(..., { recursive: true })`),
so they see both copies. Like the two existing patches, the new sites are patched in both copies,
which keeps the copies consistent.

### 4.1 S3 — historian wait (`index-b6xz3qbe.js`)

```js
var HISTORIAN_INLINE_JOIN_BUDGET_MS = 60000;                                  // 23696
function resolveHistorianInlineJoinBudget(configuredTimeoutMs) {
  const requested = configuredTimeoutMs ?? HISTORIAN_INLINE_JOIN_BUDGET_MS;
  return Math.max(0, Math.min(requested, HISTORIAN_INLINE_JOIN_BUDGET_MS));  // 23699
}
```

- Only caller: line 23830, `resolveHistorianInlineJoinBudget(args.historianTimeoutMs)`.
- `args.historianTimeoutMs` is `historianRun?.timeoutMs ?? deps.historianTimeoutMs`
  (lines 24696, 24986); `historianRun.timeoutMs` is `fresh.historian_timeout_ms`
  (`context-fk8e3h9p.js:6120`), the configured value (1,800,000 in
  `/home/mavasbel/.config/cortexkit/magic-context.jsonc`).
- With the clamp the wait is never above 60 s. Replacing the return value with
  `Math.max(0, requested)` makes it the configured value, and 60 s only when none is set.
- Line 23953 tells the user "up to 60 seconds" from the constant. It must say the wait actually
  used. Lines 23830 and 23953 are both inside `runCompartmentPhaseImpl(args)` (line 23750; 23830
  is in its nested `awaitCompartmentRun(activeRun, reason)`, line 23821, which uses the outer
  `args`). So the status text is patched to
  `${resolveHistorianInlineJoinBudget(args.historianTimeoutMs) / 1000}`, the same value the wait uses.
- The refusal message comes from `historianJoinFailClosedMessage` (line 23701), which reads
  `input.budgetMs`, the budget returned by the phase (`historianJoinBudgetMs`), so it reports the
  configured wait without a further change.
