const timedTransform = (input, output) => withTransformTimingSummary(async () => {

  try {
    await transform(input, output);

    if (sessionId && !deps.compactionOff && error instanceof EmergencyFailClosedError)

## Which sites stay, and why nothing is dropped

Upstream 0.49.37 added `recordUsageRefusal` / `shouldResetRefusedUsage`
(`dist/index-216tae7b.js`, `transform-context-state.ts`). The reset it enables is conditional:

```js
function shouldResetRefusedUsage(db, sessionId, meta, liveReading) {
  const refusedAt = refusals?.get(sessionId);
  if (refusedAt === undefined) return false;
  const readingAt = liveReading?.hasUsageTokens ? liveReading.updatedAt : meta.lastResponseTime;
  if (readingAt > refusedAt) { refusals?.delete(sessionId); return false; }
  const now = Date.now();
  const foldedAt = meta.cachedM0MaterializedAt ?? 0;
  if (foldedAt > refusedAt && foldedAt <= now) return true;
  return !!db.prepare("SELECT 1 FROM compartments …created_at > ? …").get(sessionId, getHarness2(), refusedAt, now);
}
```

A newer reading or a fold/compartment created after the refusal resets the reading; with neither, the
refused usage is used again and the next turn is refused again — the failure #828 describes when the
historian never finishes. Our `loadedSessions.delete(sessionId)` in the catch resets unconditionally on the
next pass, so both sites stay. Nothing is obsolete, so no sandbox reproduction was needed to justify a
removal; none was run.
