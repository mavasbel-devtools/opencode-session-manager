# OpenCode 2.0.32 store schema

What changes in `opencode.db` from OpenCode 2.0.26 to 2.0.32, read on 2026-10-18.

## Source

`npm pack @opencode/cli-linux-x64@2.0.32` (integrity
`sha512-Q50ofBQ3gdwjD6ZQhrVR8fVlm8D2xPMshy4dynY6l6b+qLdKgBSJ9WpoaDyrQX1YWmf2s7IN4RbXmoXXdJitDA==`,
equal to the registry's `dist.integrity`), unpacked into
`~/.cache/opencode-session-manager/hosts/2.0.32/`; `bin/opencode --version` prints `opencode v2.0.32`.

Two stores were produced with `opencode session list --standalone --format json`, each in a sandbox
(`XDG_DATA_HOME`, `XDG_STATE_HOME`, `XDG_CACHE_HOME`, `XDG_CONFIG_HOME` pointing at a temporary
folder):

1. an empty profile, which OpenCode 2.0.32 created from scratch;
2. a `VACUUM INTO` copy of this machine's 2.0.26 store, which OpenCode 2.0.32 migrated
   (`pragma integrity_check`: ok).

## Migrations

Both stores end at `20261010180456_project_time_archived`; the migrated copy's previous last
migration is `20261007190000_azure_cli_external_credential` (2.0.26).

## Schema difference

`bun scripts/schema.ts fixture` of the migrated copy (`tests/support/sessions/opencode-2.0.32.sql`)
compared with `tests/support/sessions/opencode-2.0.24.sql`: exactly one line differs — the `project`
table gains `` `time_archived` integer `` (nullable). No table, index or other column changes.

The store OpenCode 2.0.32 creates from scratch has the same tables and columns; it differs only in
the text of some `CREATE TABLE` statements (columns declared inline rather than appended by
`ALTER TABLE`, backquoted rather than double-quoted names) and in not having the OpenCode 1 tables
(`session`, `message`, `part`, `todo`, `session_share`) that a migrated store keeps.

## What OpenCode 2.0.32 does with it

On its first start against the migrated copy, OpenCode 2.0.32 set `time_archived` on 22 of the 44
projects — the projects whose folder no longer exists on this machine (Windows-era temporary
folders, the emptied `~/Documents/Work/ITAM/Cursos/*` folders, removed tool folders). Its project
list hides archived projects.

## Consequences for opencode-session-manager

- `src/infrastructure/adapters/outbound/sqlite/schema/opencode.ts` is generated from
  `opencode-2.0.32.sql`; `project.time_archived` is known, and stores without it (2.0.24–2.0.26) are
  read and written through the columns they have.
- `sync` copies a project record's `time_archived` like any other column when it makes the target's
  project from the source's record.
- Stores at different migrations are still refused (`OpenCodeFormatMismatchError`): a 2.0.26 store
  and a 2.0.32 store do not sync until both run 2.0.32 once.
