# Magic Context 0.49.7: the same files, the same patch

Evidence for adding Magic Context 0.49.7 to `execute-threshold-min` (`patches/execute-threshold-min.ts`),
read from the published package on 2026-10-16. The earlier reasoning is in
`2026-10-11-19-37-magic-context-0.47.0-execute-threshold.md` and the later checks up to
`2026-10-14-22-08-magic-context-0.49.2-execute-threshold.md`; this document only records what 0.49.7
shows, compared with the 0.49.2 copy installed on this machine (patched; the patch's own one-character
change is the only expected difference). 0.49.3–0.49.6 were never installed here and are not added.

## 1. The published files

`npm pack @cortexkit/opencode-magic-context@0.49.7` gives
`cortexkit-opencode-magic-context-0.49.7.tgz`; its sha512 computed locally equals the registry's
`dist.integrity`,
`sha512-dnvLs+YRidxchyjuu/slNlGPkvzuuucRJ1qisCFBzA+s3XgzvsGKiiD6ob05oqThLSLHZW834Gd1nn8qP194Ew==`
(npm publish time 2026-10-16T20:38:40.924Z UTC; GitHub release v0.49.7, commit `cb9ba1d`).

Among all `dist/**/*.js` files, the same two contain `min(20).max(90`, three times each, and both are
byte-identical to 0.49.2's (`cmp` against `tests/fixtures/magic-context-0.49.2/`):

The OpenCode 2 file is still loaded: ten 0.49.7 chunks import `server-cw6521wn.js`, among them the

hit is the type declaration `dist/config/schema/magic-context.d.ts`). Unmodified copies of the two
files are the test fixture `tests/fixtures/magic-context-0.49.7/`.

## 2. The schema still rejects values below 20

`package/src/config/schema/magic-context.ts` is identical to 0.49.2's apart from indentation (`diff`
after stripping leading whitespace: no difference). Running the 0.49.7 source schema
(`MagicContextConfigSchema.safeParse`) on the live `~/.config/cortexkit/magic-context.jsonc` gives
exactly one issue: `execute_threshold_percentage` "Too small: expected number to be >=20". With that
one value set to 20 the configuration is valid, including the new
`execute_threshold_tokens` (`antigravity/gemini`, `antigravity/claude`, `antigravity/gpt`: 80000).

## 3. The code that uses the threshold is unchanged

- Function texts extracted from `dist/v2/*.js` (brace-matched, log helper numbering normalised) are
  identical in 0.49.2 and 0.49.7: `resolveExecuteThresholdDetail`, `modelKeyLookupOrder`,
  `resolveTokensMatchWithKey`, `resolveModelKey`, `resolveContextLimit`, `isFinitePositive`,
  `normalizeTrustedPercentageThresholds`, `makeProjectThresholdWarning`.
- All 7 call sites of `resolveExecuteThresholdDetail` in the OpenCode 2 context chunk (500 characters
  of context each) are identical.
- Every expression mentioning `executeThresholdPercentage`, `execute_threshold_percentage` or
  `ExecuteThreshold` (60 characters each side, digits removed): 114 in the OpenCode 2 build and 140 in
  the OpenCode 1 build in both versions; the single differing expression in each is the schema line
  itself, shifted by one character by the patch applied to the 0.49.2 copy.
- `MAX_EXECUTE_THRESHOLD = 90`, `PROACTIVE_TRIGGER_OFFSET_PERCENTAGE = 2`: 13 still gives 11.
- The log lines `effect` reads are present once each, as in 0.49.2: "transform threshold: model=",
  "proactiveFloor=", "below proactive floor", "config reload failed".
- Functions other tools rely on are unchanged: `seedV2ForkFromParent`, `openDatabaseAsync`.

## 4. Storage and release notes

`LATEST_SUPPORTED_VERSION = 95`, highest migration `version: 95`. The release notes of 0.49.3, 0.49.4,
0.49.5, 0.49.6 and 0.49.7 each state "No migration. `context.db` stays at schema 95 and `store.db` at
schema 63", and list no new or changed configuration keys.

So the same three replacements make a configured 13 work as 13 on 0.49.7. The e2e test
`tests/e2e/lifecycle.test.ts` applies and undoes the patch on the fixture files and checks both
checksums. After updating to 0.49.7: `opencode-magic-context-patches apply`, restart OpenCode, then
`opencode-magic-context-patches effect` (expects `respected`).
