# Magic Context 0.49.0: the same schema minimum, the same patch

Evidence for adding Magic Context 0.49.0 to `execute-threshold-min` (`patches/execute-threshold-min.ts`),
read from the published package on 2026-10-12. The 0.47.0 reasoning is in
`2026-10-11-19-37-magic-context-0.47.0-execute-threshold.md`, the 0.48.0 check in
`2026-10-12-15-13-magic-context-0.48.0-execute-threshold.md`; this document only records what 0.49.0
shows, compared with the published 0.48.0 package.

## 1. The published files

`npm pack @cortexkit/opencode-magic-context@0.49.0` gives
`cortexkit-opencode-magic-context-0.49.0.tgz`, integrity
`sha512-y1AtvSLM4Vkfcg90DIlofJTxg/HXv1chxr4BovOYsKg+V0so8DGPYUD8J5rWA+MneSY6D36p2sSN7l+u14Hzow==`
(npm publish time 2026-10-13T04:49:25.670Z UTC).

Among all `dist/**/*.js` files, two contain `min(20).max(90`, three times each:

fixture `tests/fixtures/magic-context-0.49.0/` (see its NOTICE.md).

## 2. The schema still rejects values below 20

`package/src/config/schema/magic-context.ts` is byte-identical between 0.48.0 and 0.49.0 (`diff -rq`
of the two packages' `src/` lists only `shared/auto-search-lifecycle.ts`, `shared/logger.ts`,
`shared/project-directory-key.ts` and two new `shared/` files). Compiled:
`dist/v2/server-zm570tr2.js` line 5613 and `dist/index-kq57tdf0.js` line 5636 start
`execute_threshold_percentage: union([` followed by the three `number2().min(20).max(90,
EXECUTE_THRESHOLD_CAP_MESSAGE)` calls (plain number, `default` key, per-model catch-all), as shown
by `opencode-magic-context-patches inspect --version 0.49.0` run on the unpacked tarball in a
sandboxed home.

Running the 0.49.0 source schema on the live `~/.config/cortexkit/magic-context.jsonc` gives exactly
one issue: `execute_threshold_percentage` "Too small: expected number to be >=20". Every other
setting is accepted.

## 3. The code that uses the threshold still has no lower bound

- `resolveExecuteThresholdDetail` (OpenCode 2: `dist/v2/context-crbt6p1y.js` line 1790; OpenCode 1:
  `dist/index-h2py7207.js`) is textually identical to 0.48.0's (`dist/v2/context-sf98kstd.js`,
  `dist/index-0an7742d.js`). It replaces the value only when it is not finite or negative
  (line 1848) and caps it at the top (line 1851, `Math.min(resolved, MAX_EXECUTE_THRESHOLD)`,
  `MAX_EXECUTE_THRESHOLD = 90` in `dist/v2/server-x4hscabv.js` line 1360).
- The proactive historian trigger (line 6111) is `Math.max(0, executeThresholdPercentage -
  PROACTIVE_TRIGGER_OFFSET_PERCENTAGE)` with `PROACTIVE_TRIGGER_OFFSET_PERCENTAGE = 2` (line 6054):
  13 still gives 11.
- Wrapup sizing (`dist/v2/server-x4hscabv.js` lines 17698 and 18653) multiplies the context limit
  by the percentage with `Math.max(1, …)`.
- Every expression in `dist/v2/*.js` and in `dist/*.js` that mentions `executeThresholdPercentage`,
  `execute_threshold_percentage` or `ExecuteThreshold` (up to 60 characters on each side, digits
  removed) is the same set in 0.48.0 and 0.49.0: 78 distinct expressions in the OpenCode 2 build,
  96 in the OpenCode 1 build.

## 4. Storage

The Magic Context database format stays 95 (the highest migration `version: 95` and
`VERSION = 95` in `dist/v2/*.js`, as in 0.48.0).

So the same three replacements make a configured 13 work as 13 on 0.49.0. The e2e test
`tests/e2e/lifecycle.test.ts` applies and undoes the patch on the fixture files and checks both
checksums. After updating to 0.49.0: `opencode-magic-context-patches apply`, restart OpenCode, then
`opencode-magic-context-patches effect` (expects `respected`).
