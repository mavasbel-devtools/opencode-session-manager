# Magic Context 0.49.15: the same two files, the same patch

Evidence for adding Magic Context 0.49.15 to `execute-threshold-min` (`patches/execute-threshold-min.ts`),
read from the published packages on 2026-10-20. Earlier reasoning: from
`2026-10-11-19-37-magic-context-0.47.0-execute-threshold.md` to
`2026-10-19-16-03-magic-context-0.49.13-execute-threshold.md`. This document compares 0.49.15 with
the pristine published 0.49.13 (`npm pack @cortexkit/opencode-magic-context@0.49.13`, integrity
`sha512-cIz9hhZ2cypyvrRnFsqJ7NxergxqqKrt8a7Ldi842vQMh3STq4sJ78A9TC+7Aun4y4w6m5KvvqQpSLguAsZQow==`,
equal to the registry's). 0.49.14 (npm 2026-10-20T06:27:04Z) was skipped: it was never pinned or
installed here, and 0.49.15 is the registry's `latest`.

## 2. The schema still rejects values below 20

`package/src/config/` is identical in 0.49.13 and 0.49.15 (`diff -r`, exit 0), and so is
`dist/config/` (`diff -rq`, no output). Running the 0.49.15 source schema
(`MagicContextConfigSchema.safeParse` from the package's `package/src/config/schema/magic-context.ts`, zod and jsonc-parser
from the installed 0.49.13 copy) on the live `~/.config/cortexkit/magic-context.jsonc` gives exactly
one issue: `execute_threshold_percentage` "Too small: expected number to be >=20". With that one value
set to 20 the configuration is valid.

## 3. The code that uses the threshold is unchanged

Measured with a script over every `.js` file, once in `dist/v2` and once in all of `dist`. Function
texts are brace-matched; whitespace and numeric identifier suffixes are normalised.

- Identical function texts in both versions: `resolveExecuteThresholdDetail`, `modelKeyLookupOrder`,
  `resolveTokensMatchWithKey`, `resolveModelKey`, `resolveContextLimit`, `isFinitePositive`,
  `normalizeTrustedPercentageThresholds`, `makeProjectThresholdWarning`, `resolveHistoryBudgetTokens`.
- All call sites of `resolveExecuteThresholdDetail(` (6 in `dist/v2`, 14 in `dist`) are identical
  with 300 characters of context on each side.
- Every `executeThresholdPercentage: …` assignment (21 in `dist/v2`, 46 in `dist`) is the same.
- Every expression mentioning `executeThresholdPercentage`, `execute_threshold_percentage` or
  `ExecuteThreshold`, with 60 characters on each side and digits removed: 122 in `dist/v2` and 270 in
  `dist` in both versions. One differs per build: the line before
  `const relativePostDropTarget = executeThresholdPercentage * POST_DROP_TARGET_RATIO;` (in
  `context-4qczzck7.js`) now passes one more argument, `eligiblePendingDropTagIds`, to
  `estimateProjectedPostDropPercentage` (v0.49.14 release note: "Compression now counts only removals that will
  really shrink the request"). The threshold expression itself is unchanged.
- `MAX_EXECUTE_THRESHOLD = 90` and `PROACTIVE_TRIGGER_OFFSET_PERCENTAGE = 2` are unchanged, so 13
  still gives 11. `EXECUTE_THRESHOLD_CAP_MESSAGE` appears 4 times per build, as before.
- The log lines `effect` reads are present as in 0.49.13 (per build): "transform threshold: model="
  (1), "proactiveFloor=" (1), "below proactive floor" (2), "config reload failed" (1), "invalid
  value" (4).
- Functions other tools rely on are unchanged: `seedV2ForkFromParent`, `openDatabaseAsync`.

## 4. Storage and release notes

`LATEST_SUPPORTED_VERSION = 95`, highest migration `version: 95`, in both builds. The release notes of
v0.49.14 and v0.49.15 both state "No migration. `context.db` stays at schema 95 and `store.db` at
schema 63". Neither lists a configuration or threshold change. v0.49.15 also says "Reloading the
OpenCode 2 plugin stops its old background work … shared database readers close when the last instance
releases them".

So the same three replacements make a configured 13 work as 13 on 0.49.15. The e2e test
`tests/e2e/lifecycle.test.ts` applies and undoes the patch on the fixture files and checks both
checksums. After updating to 0.49.15: `opencode-magic-context-patches apply`, restart OpenCode, then
`opencode-magic-context-patches effect` (expects `respected`).
